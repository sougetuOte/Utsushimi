# 0003. LLM は Anthropic の公式 Python SDK で呼び、段1は1つのモデル（claude-opus-5-5）を役割ごとの effort で使い分ける

- 日付：2026-09-23
- 状態：採用
- 決めた人：主人

## 背景

LLM は Anthropic API（2026-09-23 主人の制約）。言語は Python（0001）。
段1で LLM を使う場面は、対話の返事、キャラ作り（連想を広げる・自分で調べる。BH-07・BH-10・BH-11）、日記の蒸留（BH-15）、
主人についての記録の更新判断（BH-18）、人格のぶれの点検（BH-23）である。
前身はモデルを「対話用・記憶整理用・前処理用」の3役に分け、対話用だけを上げる方針だった（`docs/concept.md` §9）。
API キーは主人の物で、リポジトリは public である（`CLAUDE.md` §2）。

## 決定

- **公式 SDK `anthropic`（Python）の非同期クライアント**で呼ぶ。生の HTTP は使わない。
- **段1は1つのモデル `claude-opus-5-5` で始める**（2026-09-23 主人決定）。役割ごとに `effort` を**明示して**変える
  （このモデルの既定は `medium`。対話は明示、日記・更新判断・点検は低め）。
  モデルを役割で分けるのは、実際の使用量と費用を測ってから主人が決める。モデル ID はコードに書かず、設定ファイルに置く。
- このモデルでは思考を切れない（`effort` だけが調整の口）。道具を強制する `tool_choice`（`any` / `tool`）は使えない。
  会話の履歴は追記だけにし、過去の発言を書き換えない（思考ブロックが無効になる）。
  返事の `stop_reason` が `refusal` のときは、本文を読む前に分岐する。
- **キャラ作りで「自分で調べる」は、サーバー側の web search ツール（`web_search_20260209`）**を使う。検索 API のキーを別に持たない。
- **人格の根っこと口調の見本は、プロンプトの先頭に固定して置き、プロンプトキャッシュを効かせる。**時刻や検索結果など毎回変わる物はその後ろに置く。
- **API キーは `data/` と同じく git の外**：リポジトリ直下の `.env`（`ANTHROPIC_API_KEY`）を起動時に読む。`.env` は `.gitignore` 済み。

## 結果

- SDK の再試行・タイムアウト・型付きの例外をそのまま使える。
- 1モデルならプロンプトキャッシュが1つの名前空間にまとまる。役割ごとにモデルを分けると、キャッシュも分かれる（claude-api スキルの指針）。
- web search がサーバー側なので、段1の BH-11 に外部の検索サービスの選定が要らない。
- 引き受けるもの：
  - 本フェーズでは API を実際に呼んでいない（`goal.md` のやらないこと）。**呼び出しの実測は段1の最初のタスク**になる
  - `claude-opus-5-5` は100万トークンあたり入力 $4 / 出力 $20。2026-09-22 に出たばかりで、実運用の報告はまだ少ない。常駐して自分から動く段2で費用が効いてくる
- 後で効く縛り：Anthropic 以外の LLM へ移るときは、呼び出しの層を差し替えることになる。

## 却下した案

| 案 | 理由 |
|---|---|
| 最初から役割ごとにモデルを分ける（前身の方式） | 測る前に安さを取ることになる。キャッシュが分かれる。段1の呼び出し回数は少なく、分ける利得が見えていない |
| 生の HTTP（`httpx` 等で直接） | 公式 SDK がある言語では使わない。再試行・型・ストリーミングを自前で持つことになる |
| ローカル LLM・他社 | 主人の制約（LLM は Anthropic API）で候補外 |
| `claude-opus-5` を既定にする | 公開から時間が経っていて落ち着いているが、主人が `claude-opus-5-5` を選んだ（2026-09-23）。設定ファイルで戻せる |

## 消滅条件

- モデルの世代が変わったら、既定のモデルを見直す
- 段2（自分から動く）で費用を測って、役割でモデルを分けると決めたら、この ADR を置き換える
