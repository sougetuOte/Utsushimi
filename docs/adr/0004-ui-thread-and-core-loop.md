# 0004. 画面のスレッドと、asyncio で回る「核」のスレッドの2本に分け、核が記憶と LLM とメインループを一手に持つ

- 日付：2026-09-23
- 状態：採用
- 決めた人：主人

## 背景

禁則「主人の入力が常に最優先で、自律的なふるまいは入力が来たら即座に引く」（`CLAUDE.md` §0）。
保護指定2「メインループは止まらない。幾つかの行動予定が回り、やる／やらないは行動予定の活性で制御する」。
前身は並行に動く部分の間で資源を受け渡して落ちた（`docs/lessons.md` Bug-2・L-1・B-7）。
LLM の呼び出しは数秒かかり、その間も画面は固まってはならない（S5）。

## 決定

- スレッドは2本。**画面のスレッド**（Qt のイベントループ）と、**核のスレッド**（asyncio のイベントループ1本）。
- **核が SQLite の接続・LLM のクライアント・メインループ（行動予定の見回り）を一手に持つ。**他のスレッドはこれらに触らない。
- 渡し方は2つだけ：画面 → 核は `loop.call_soon_threadsafe`、核 → 画面は Qt のシグナル（キュー接続）。物ではなく値（文字列・小さな dict）を渡す。
- **主人の入力は、核が受け取った時点で LLM より先にコミット**する（0002）。
- **主人の入力が来たら、核は走っている自律の仕事（asyncio のタスク）を `cancel()` で止め、すべての行動予定を非活性に戻す。**
  メインループそのものは止めない。

## 結果

- 資源の持ち主が1人なので、前身の Bug-2 の型（スレッドをまたいで資源を受け渡して落ちる）が起きる場所が、2つの渡し口に限られる。
- asyncio のタスクは途中で取り消せる。スレッドで回した HTTP 呼び出しは途中で止める口が無い。
- 保護指定2 のメインループは核の中の常駐タスクとして置く。段1では行動予定を持たず、口だけ残す。
- スパイクでは「裏のスレッド ＋ Qt のシグナル」で、待ちの最中の打鍵が通り、UI タイマーの最大間隔は 29ms だった（S5）。
- 引き受けるもの：
  - **取り消し（`cancel()`）で HTTP 呼び出しが実際にすぐ止まるかは測っていない。**段2で自律の仕事を足すタスクの完了条件で確かめる
  - SQLite の書込みは核のスレッドで同期で行う。1発言の書込みは短いが、日記の作成など重い処理が入ったら核が詰まる。詰まったら核の中で別に逃がす
- 後で効く縛り：GUI を差し替えても、核の側は変えずに済む（画面との口が2つだけなので）。

## 却下した案

| 案 | 理由 |
|---|---|
| 画面のスレッドで直接 DB に書き、LLM だけ裏のスレッドで呼ぶ（スパイクの形） | 保存は最も単純だが、DB を2つのスレッドが触る形になる。前身の Bug-2 の型に近づく |
| Qt と asyncio を1本のスレッドで回す（PySide6 の QtAsyncio など） | スレッドは減るが、核の同期の処理（SQLite・前処理）が画面を止める。成熟度も確かめていない |
| 呼び出しごとにスレッドを起こす | 取り消しの口が無い。「入力が来たら即座に引く」を満たせない |
| 別プロセスに分ける | 段1には過剰。受け渡しが直列化になり、落ち方も増える |

## 消滅条件

- 核のスレッドの処理で画面が固まることが実測で出たら見直す
- GUI を Qt 以外に差し替えたら見直す
