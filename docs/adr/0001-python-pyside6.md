# 0001. 本体は Python ＋ PySide6（Qt 6）で書き、トレイに常駐させる

- 日付：2026-09-23
- 状態：提案
- 決めた人：主人

## 背景

前身からはコードを持ち込まず、技術選定を決め直す（`CLAUDE.md` §1）。先に決まっている制約は、主人の機械だけで動けばよい（配布しない）、
LLM は Anthropic API、言語と GUI は縛らない（2026-09-23 主人）。
常駐 GUI の核（枠なしの窓・ヘリの突っつき・トレイ・即時の保存・裏の処理中も固まらない・2回目の起動・コンソールを出さない起動）は、
机上では決まらない。3候補を Windows 11 で実際に起動して測った（`docs/research/2026-09-23-phase1-spike.md`）。
これが決まらないと、記憶の器（0002）・LLM の呼び方（0003）・並行の形（0004）が決まらない。

## 決定

本体は **Python（3.11 以上。版は uv のプロジェクト設定で固定）＋ PySide6（Qt 6）**で書く。
窓は Qt の枠なし窓、トレイは `QSystemTrayIcon`。主人の起動方法は `pythonw.exe` を指すショートカットとする。

## 結果

- スパイクの S1〜S7 は3候補とも「可」で、差は出なかった。決め手は S1〜S7 の外にある：
  - **常駐の重さ**：10秒放置後の作業セット pyside6 85MB（1プロセス）／wpf 149MB／tauri 393MB（WebView2 を含む7プロセス）。起動は pyside6 約 510ms が最短
  - **LLM の SDK**：Anthropic の公式 SDK が Python にある。tauri（Rust）には無い（0003）
  - **言語が1つで済む**：tauri は Rust と HTML/JS の2つ、wpf はトレイのために WPF と WinForms を混ぜる
- S2（ヘリと内側の区別）は、アプリ全体のイベントフィルタで押された位置を窓の座標に直して判定した。保護指定1 はこの形で満たせる。
- 引き受けるもの：
  - Python の配布は面倒だが、主人の機械だけで動けばよいので問わない。venv と `pythonw.exe` のショートカットで足りる（S7）
  - PySide6 は LGPLv3。本体は MIT のまま、PySide6 を改変せずに使う
  - スパイクの窓はタスクバーにボタンを出した。常駐する相棒がタスクバーに出るかは段1の設計で決める
- 後で効く縛り：画像ボディ（拡張口）の半透明の窓は Qt で作る前提になる（未測）。

## 却下した案

| 案 | 理由 |
|---|---|
| Tauri（Rust ＋ WebView2） | S1〜S7 は可（S1 は権限 `core:window:allow-start-dragging` を足して可）。常駐の重さが 393MB・7プロセスで最も重い。Rust に Anthropic の公式 SDK が無く、生の HTTP か、TypeScript の SDK を WebView（API キーが画面側に入る）か Node の副プロセスで動かすことになる。言語が2つになる |
| .NET WPF（C#） | S1〜S7 は可。C# の公式 SDK もある。常駐 149MB・起動約 865ms で pyside6 より重く遅い。WPF 単体にトレイが無く、WinForms の `NotifyIcon` を混ぜる。.NET SDK の導入が要った |
| tkinter（前身の選定） | 測っていない。前身は per-pixel 透過が要る段で PyQt6 / PySide6 へ移る計画だった（`docs/concept.md` §7.4）。移る先が分かっているなら最初から移る先を使う |
