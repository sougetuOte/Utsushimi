## 1. コンセプト

> 人格を持ち、記憶を引き継ぐ、1対1の常駐デスクトップの相棒。
> 人格の根っこは最初に決めたら変わらない。根っこ以外が、共に過ごした歴史（エピソード）によって変わっていく。

主人の出発点は次の5つだった（`K/docs/memos/方向性.md:1-6`）。

- デスクトップマスコット
- 記憶の引き継ぎができる
- 人格の一貫性を大事にする
- できるだけシンプル
- できるだけテキスト系

名前の由来は「未だ神でないがゆえに」、副題 "Not yet divine. Not yet free."（`K/docs/memos/方向性.md:9-10`）。Utsushimi はこの副題を継ぐ。

前身の統合設計はコンセプトを次のように言い切った（`K/docs/memos/middle-draft/04-unified-design.md:8-16`）。

- ウィンドウのヘリをボディ代わりに、突っつくと反応する
- セッションをまたいで記憶が継続する
- 人格は初期生成後に凍結し、歴史（エピソード）の蓄積で関係が深まる
- **同じ入力でも同じキャラは二度と生まれない（ゆらぎによる唯一性）**

主人はキャラについて、根っこは変わらず、最初のパラメータを決めた後は根っこ以外が変わりながら付き合うことになる、と書いている。
さらに、ユーザーが書ける部分・書けない部分の線引きが重要であり、同じ入力でも AI が調べながら作る過程のゆらぎが「唯一無二」をつくる、とした
（`K/docs/memos/2026-03-03-char.md:9-11`）。

主人が最初に求めた設計姿勢は「ややこしい技術はなるべく省く」「シンプルな構造に限り無くこだわる」「色々拡張したいので」である（`K/docs/memos/方向性.md:23-26`）。

**食い違い（名前の置き換え）**：前身は自らを「常駐テキストマスコット」と呼んだ（`K/docs/memos/middle-draft/04-unified-design.md:10`）。
Utsushimi は「相棒」と呼ぶ（`CLAUDE.md` §0、2026-09-23 主人決定）。指す中身（1対1・常駐・テキスト主体）は変わらない。

## 2. 完成形 ── 1対1の相棒（AITuber は拡張口）

**Utsushimi の完成形は1対1の相棒である。**AITuber（1対多の配信）は拡張口として残すが、設計の制約は1対1の側から決める（`CLAUDE.md` §0）。

前身はこの差を表で整理していた。これがそのまま、1対1を優先する理由になる
（`K/docs/memos/middle-draft/07-character-design.md:453-462`、要約版は `K/docs/memos/middle-draft/04-unified-design.md:18-27`）。

| 特性 | VTuber / AITuber | 相棒（前身のデスクトップマスコット） |
|---|---|---|
| 関係性 | 1対多（配信者と視聴者） | **1対1（パートナー）** |
| 稼働形態 | 配信時間のみ | **常時起動（常にそばにいる）** |
| 表現媒体 | 音声＋映像＋チャット | **テキスト主体** |
| インタラクション頻度 | 高密度・短時間 | **低密度・長時間** |
| 注意の奪い合い | コンテンツとして注意を集める | **ユーザーの作業を邪魔しない** |
| 人格の共同構築 | ファンコミュニティ全体 | **ユーザー1人とキャラ1体** |

1対1で「邪魔しない」ことから導かれる設計上の帰結（`K/docs/memos/middle-draft/07-character-design.md:466-476`）。

- 常時起動のマスコットに求められるのは「面白い」ではなく「心地よい」
- 社交性（性格軸）の既定は「聞かれたら答える、時々自分から話しかける」程度。高すぎると鬱陶しい
- 自律発言は、talk 欲求の閾値を高めにして抑える
- ユーモアは「クスッとする」程度。ダジャレ連発やハイテンションは配信向き
- 沈黙破り（S7）のトーンが「うるさい」と感じられたら、マスコットとして致命的

配信型の知見のうち、1対1に持ち込まないもの（`K/docs/memos/middle-draft/07-character-design.md:444-447`）。

- 視聴者の反応で盛り上がる「カオス」は、1対1では不快になりうる
- 独自 LLM の学習はスコープ外
- 配信中に開発者が手で直す介入は、常駐する相棒ではできない。自律的な一貫性維持が要る

**食い違い（AITuber の扱い）**：前身は AITuber を「根本的に異なる設計制約を持つ」比較対象として扱い、拡張の行き先としては置いていない
（`K/docs/memos/middle-draft/04-unified-design.md:18-20`）。
主人のメモは VTuber・AITuber の知見も取り入れるよう求めていた（`K/docs/memos/2026-03-03-char.md:8`）。
Utsushimi は `CLAUDE.md` §0 に従い、**AITuber を拡張口として残す**。ただし「邪魔しない」と「注意を集める」は逆を向くので、
拡張口が1対1の側の制約（主人の入力が最優先・うるさくない側に倒す）を曲げてはならない。

## 3. 道のり ── 前身の Phase 1〜4 を相棒として整理し直す

前身のロードマップは機能の束で切られていた（`K/docs/memos/middle-draft/04-unified-design.md:359-392`、
同じ内容の一覧表は `K/docs/memos/middle-draft/03-architecture.md:162-171`）。
ここでは各段を**主人から見て相棒がどうなるか**で言い直す。技術の置き換え（エンジン移行など）は道のりの節目にしない。

前身は Phase 2b の途中で止まっている（`CLAUDE.md` §1）。どの振る舞いが実装済みかは `docs/behaviors.md` に分ける。

### 段1「そばにいて、話せて、覚えている」── 前身 Phase 1（基盤・MVP）

前身 Phase 1 の中身（`K/docs/memos/middle-draft/04-unified-design.md:361-367`）を、相棒の側から言うと：

- 常駐して、最小化してもそばにいる（`K/docs/memos/方向性.md:13`）
- テキストで話せる。ウィンドウのヘリを突っつくと反応する
- 最初の起動で、主人と AI が一緒にキャラを生み、**ゆらぎ**を経て根っこ（C1〜C11・S1〜S7）を**凍結**する
- 話したことは即座に残り、日ごとの日記に蒸留され、翌日以降も覚えている
- 異常終了や電源断でも記憶を失わない

### 段2「自分から動く。でも邪魔しない」── 前身 Phase 2（自律性）

前身 Phase 2 の中身（`K/docs/memos/middle-draft/04-unified-design.md:369-377`）を、相棒の側から言うと：

- メインループが止まらず、欲求（talk / curiosity / reflect / rest）に応じて**行動予定**が活性化する
- 時々ひとりでつぶやく。ただし控えめで、**主人が入力したら即座に全部引く**
- 気になった話題を**自分で調べ**、その結果が興味の広がり（L1）として残る
- 根っこ以外（L1〜L6）が本格的に変わり始める
- 主人が相棒の記憶（日記・検索）を覗ける

### 段3「相手を読み、自分の興味を育てる」── 前身 Phase 3（知性）

前身 Phase 3 の中身（`K/docs/memos/middle-draft/04-unified-design.md:381-386`）を、相棒の側から言うと：

- 調べたことから派生して次の興味が生まれ、**興味の系譜**ができる
- 主人の文面の調子（句読点・記号・敬語かどうか）から、今の様子を汲み取る（Theory of Mind）
- 使ううちに新しい口癖が生まれる。ただし主人の承認を経て、凍結殻の外に足すだけ
- 変化の提案（関係性・感情の傾向）を主人がまとめて承認できる場所ができる

前身 Phase 3 には調査用エンジンの移行（クラウドからローカル LLM へ）も入っていたが、これは技術の差し替えであり、相棒の振る舞いは変えない。

### 段4「長く一緒にいても崩れない」── 前身 Phase 4（成熟）

前身 Phase 4 の中身（`K/docs/memos/middle-draft/04-unified-design.md:388-392`）を、相棒の側から言うと：

- 何か月も付き合っても人格がぶれない（整合性チェックの精度を上げる）
- 日記の蓄積から月単位の傾向を掴む
- 長く付き合って記憶が増えても、応答に使う文脈の量を適切に保つ
- 主人の鍵と、主人との記憶を守る（鍵の保管・ローカルデータの暗号化）

### 拡張口（段の外）

- **ボディの画像化**：ヘリだけのボディから、透過 PNG を状態で差し替える方式へ（後述 §7）
- **AITuber**：1対多の配信。§2 のとおり、1対1の制約を曲げない範囲で

## 4. 記憶（前身 01）

### 4.1 3層ロード

前身は記憶を「いつ文脈に入れるか」で3層に分けた（`K/docs/memos/middle-draft/01-memory-system.md:17-38`、`K/docs/memos/middle-draft/04-unified-design.md:241-247`）。

| 層 | 中身（前身での名前） | 入るタイミング |
|---|---|---|
| Hot | 人格核（persona_core）・ユーザー情報（human_block）・口調の参照例（style_samples）・傾向メモ（personality_trends）・いまの会話 | 毎回 |
| Warm | 直近5日分の日次サマリー（日記） | セッション開始時 |
| Cold | 個々の会話断片（observations）・興味の系譜（curiosity_targets） | 会話中に必要なときだけ検索（上位5件） |

キャラの3層（凍結核／凍結殻／可変層、§8）と記憶の3層は 1:1 には対応しない。傾向メモは可変層だが Hot として毎回入る
（`K/docs/memos/middle-draft/07-character-design.md:56-61`）。

### 4.2 忘却曲線

Cold の検索順位に、忘却係数 R = e^(-t/S)（R: 記憶強度、t: 経過時間、S: 想起回数）を掛ける。
Hot と Warm には掛けない（常に入れるため）。前身では Phase 1 は素のキーワード検索、Phase 2 で忘却係数を足す計画だった
（`K/docs/memos/middle-draft/04-unified-design.md:249-258`）。根拠は MemoryBank（`K/docs/memos/middle-draft/01-memory-system.md:118`）。

### 4.3 ライフサイクル

（`K/docs/memos/middle-draft/04-unified-design.md:262-275`、`K/docs/memos/middle-draft/01-memory-system.md:70-89`）

- **起動時**：初回ならキャラ生成（ウィザード）へ。人格核とユーザー情報を読む。前回サマリーにしていない会話断片を見つけたら、遡って日記を作る（欠損補完）。直近5日分の日記を Warm として入れる
- **会話中**：主人の入力を**即時に書き込む**。必要なら過去の断片を検索する。ユーザー情報の更新を判断する。人格核・参照例・検索結果を文脈にして応答する
- **終了時（2層防御）**：終了の経路を2つ押さえ、どちらでも今日の未処理の断片から日記（感情の変化を含む5〜8文）を作って保存する。当日分は作り直せ、過去分は変えない
- **異常終了時**：断片は即時に書かれているので失われない。次回起動時の欠損補完が、断片と日記の日付を比べて欠けた日を作り直す

これは `CLAUDE.md` の禁則「記憶を失わない。会話は即時に永続化し、異常終了や電源断でも失わない」の、前身での具体化である。

### 4.4 ユーザー情報の自己編集の歯止め

相棒が主人について覚えたこと（human_block、キャラ体系では L6）は、AI が自分で書き換えてよい唯一のファイルである。ただし歯止めがある
（`K/docs/memos/middle-draft/04-unified-design.md:277-285`、`K/docs/memos/middle-draft/01-memory-system.md:102-108`）。

| 規則 | 中身 |
|---|---|
| 更新判断 | 主人の属性（名前・好み・習慣など）が**明示的に**出たときだけ |
| 更新タイミング | 会話ターンの後。応答とは非同期 |
| 禁止 | 推測で書くこと。既存の情報を消すこと（上書きのみ可） |
| 矛盾 | 最新の日付が勝つ（鮮度優先） |
| 枝刈り | 「今回だけ」の一時的な情報は書かない |

### 4.5 人格ドリフト防止

（`K/docs/memos/middle-draft/01-memory-system.md:93-100`）

1. 凍結後の人格核へのプログラムからの書込を禁止する
2. 口調の参照例も凍結後は本体に足さない。新しい口癖候補は傾向メモの補足欄に承認制で足す
3. 傾向メモへの書込は主人の承認制
4. 自己編集してよいのはユーザー情報だけ（変更履歴を残す）
5. 忘却曲線で、古く弱い記憶の検索順位を自然に下げる
6. 日記は「記憶の整理」であって「人格の書き換え」ではない

### 4.6 文脈への入れ方

優先順位は「ユーザー入力 ＞ セッションの記憶（Warm）＞ 検索結果（Cold）＞ ペルソナ（Hot）」。
記憶の中身はタグで包んで指示と取り違えさせない。一時情報は枝刈りし、矛盾は新しい方が勝つ
（`K/docs/memos/middle-draft/04-unified-design.md:129-140`）。

### 4.7 長期運用の見積もり

会話断片は1日に数十〜数百件、数か月で数万件。日記は1日1件で年365件（`K/docs/memos/middle-draft/04-unified-design.md:297-301`）。
前身では、断片が数万件になっても SQLite の全文検索インデックスで速度は保てる、と見積もっていた（`K/docs/memos/middle-draft/01-memory-system.md:127-133`）。

## 5. 人格と欲求（前身 02）

### 5.1 人格一貫性の5原則

（`K/docs/memos/middle-draft/02-personality-system.md:18-51`）

1. **人格核の凍結＋口調の参照例**：人格核（C1〜C11）を凍結して毎回入れ、参照例（S1〜S7、17〜25例）を常に参照させる。テキストでは口調が人格そのものなので効果が大きい（`K/docs/memos/middle-draft/02-personality-system.md:20-26`）
2. **記憶の選択的蓄積**：全部を無条件に積まない。検索は上位5件まで。日記で蒸留する（`K/docs/memos/middle-draft/02-personality-system.md:28-32`）
3. **ロールプレイ層とパーソナライゼーション層の分離**：相棒の人格（persona_core）と主人の情報（human_block）を分け、「キャラとして何を言うか」と「この人にどう言うか」を2段で決める（`K/docs/memos/middle-draft/02-personality-system.md:34-38`）
4. **応答前の簡易自己問答**：「このキャラならどう反応する？」を1問だけ内部で問う（`K/docs/memos/middle-draft/02-personality-system.md:40-44`）
5. **定期的な整合性チェック**：10〜20メッセージごと（既定15）に軽く確かめる。1対1は配信より発話頻度が低く、崩れのリスクも低いので、5メッセージごとは過大と判断した（`K/docs/memos/middle-draft/02-personality-system.md:46-51`）

監視する崩れの3類型は、キャラクター幻覚（設定外の知識の漏出）・行動記述の曖昧性・一般知識忘却
（`K/docs/memos/middle-draft/02-personality-system.md:147-151`）。

人格消失防止の束として、前身は禁忌（C10）が人格の輪郭を定めるのに本質的だと強調した（`K/docs/memos/middle-draft/04-unified-design.md:229-235`）。

### 5.2 欲求システム

欲求は「内部レベル（0.0〜1.0）」「発現閾値」「自然言語での発現形式」の組。**数値は外に一切出さない**
（`K/docs/memos/middle-draft/02-personality-system.md:55-60`）。

| 欲求 | 発火条件 | 発現形式 |
|---|---|---|
| talk | 会話の間隔が長い | ウィンドウ端のテキストの変化・つぶやき |
| curiosity | アイドル時間 × 未調査トピックの残り | 「そういえば…」的なつぶやき |
| reflect | エピソードの蓄積量が閾値を超えた | 「ちょっと考え事してた」的な内省 |
| rest | 長時間の稼働 | 応答のテンポが落ちる・短くなる |

（`K/docs/memos/middle-draft/02-personality-system.md:62-69`）

更新は5〜10秒ごとで、純粋な計算（LLM を呼ばない）。閾値を超えたときだけ LLM で発現の文を作る
（`K/docs/memos/middle-draft/02-personality-system.md:71-75`）。
欲求レベルは再起動をまたいで持ち越さない（「今の状態」だから）。未調査トピックは記憶側に残るので、curiosity は再起動後も正しく計算し直せる
（`K/docs/memos/middle-draft/02-personality-system.md:115-119`）。

### 5.3 制御規則 ── 作業の邪魔をしない

（`K/docs/memos/middle-draft/02-personality-system.md:77-87`）

- ユーザー入力は常に最優先
- **会話中は自律行動をすべて非活性に戻す**（入力の時点で即座に）
- 一定時間入力が無くなってから欲求タイマーを再開する
- 自律行動どうしの競合は欲求レベルの高さで決める
- 好奇心は、密な外部報酬が無いときに働く
- 1対1ではユーザーが唯一の相手なので、自律発言が多すぎると「うるさい」。talk の閾値は控えめにし、実運用で調整する

### 5.4 行動予定とメインループ ── 保護指定2

主人の言葉：メインループの中で幾つかの行動予定が回る。メインループは止まらない。行動予定の活性でやる・やらないを制御する
（`K/docs/memos/方向性.md:18-20`）。

前身はこれを次の形にした（`K/docs/memos/middle-draft/02-personality-system.md:91-105`）。

- 欲求ごとに行動予定を持つ。閾値を超えたら活性、実行したら非活性
- ループの1周：①UI のイベントを見る → ②入力があれば全行動予定を非活性にして対話へ → ③入力が無ければ欲求レベルを更新 → ④閾値を超えた欲求の行動予定を活性に → ⑤活性の行動予定を実行するか判定し、必要なときだけ LLM を呼ぶ

### 5.5 対話とつぶやきは同じ道を通す

対話もつぶやきも「考える → 行動（記憶検索・調査など）→ 観察 → 文を作る」の同じ流れを通す。
こうすると記憶参照と人格一貫性チェックが自律発言にも自動で効く。「対話」と「つぶやき」で道を分けない
（`K/docs/memos/middle-draft/02-personality-system.md:157-164`）。

### 5.6 相手を読む（Theory of Mind）

段階的に入れる。まず規則ベースで、句読点・記号・敬語かタメ口か・語彙の硬さから調子を読む。
1対1のテキストでは手がかりがそこに集まるので、大半はパターンで拾える。足りなければ LLM に上げる（呼び出しが1回増える分のコストを試算し直す）
（`K/docs/memos/middle-draft/02-personality-system.md:123-143`）。

## 6. 自分で調べる（前身 05）

### 6.1 位置づけ

自分で調べる仕組み（前身での名前は AgenticSearch）は**自律性の段（前身 Phase 2）の一部**。
curiosity 欲求が引き金を引き、調べる仕組みがそれを受けて調査する（`K/docs/memos/middle-draft/05-agentic-search.md:25-26`）。
発火の頻度（過剰発火の防止）は欲求システムの側が決め、調べる仕組みは発火後の流れだけを受け持つ
（`K/docs/memos/middle-draft/05-agentic-search.md:197`）。

### 6.2 流れ

（`K/docs/memos/middle-draft/05-agentic-search.md:44-70`）

1. curiosity 欲求が発火する
2. 会話の履歴から好奇心の種（キーワード・固有名）を抜き出す
3. LLM が問いを2〜4個のサブクエリに分ける
4. 検索を並列に走らせる
5. LLM が結果を1件ずつ要約し、そこから「雑味」（派生テーマの候補）を拾う
6. 本題と派生テーマを、興味の記録（前身での名前は curiosity_targets）に書く

前身の設計判断として、検索の並列実行は LLM のツール呼び出しに頼らず、プログラム側で行うと決めていた。
将来のエンジン差し替えで不具合を持ち込まないためである（`K/docs/memos/middle-draft/05-agentic-search.md:72-73`）。
調べる役の LLM は差し替え可能に抽象化し、上位の流れは変えない（`K/docs/memos/middle-draft/05-agentic-search.md:75-96`）。

### 6.3 興味の記録

1件ごとに「トピック・状態（未着手／調査中／済／失敗）・優先度（1が高く10が低い）・派生元・作成時刻・要約」を持つ
（`K/docs/memos/middle-draft/05-agentic-search.md:119-135`）。
派生元のつながりを使った「興味の系譜」（グラフ化）は段3で広げる（`K/docs/memos/middle-draft/05-agentic-search.md:137`）。

優先度の更新規則（`K/docs/memos/middle-draft/05-agentic-search.md:139-147`）：新規は中間（5）。主人がその話題に触れたら1つ上げる。調査済みになっても変えない。

検索の生の結果は保存せず、要約と派生テーマだけを残す（`K/docs/memos/middle-draft/05-agentic-search.md:149-153`）。

### 6.4 相棒にとっての意味

調べた結果は興味の広がり（L1）として積もり、次に関連する話題が出たとき「そういえばこの前〇〇のこと調べたんだけどね」と言える。
興味の方向（「歴史に興味がある」）は根っこ、知識の広がり（「ビザンツ帝国に詳しい」）は枝である
（`K/docs/memos/middle-draft/07-character-design.md:199-212`）。

調べる仕組みは、キャラ生成のゆらぎ（§8.9 の Step 3）にも使う。これが保護指定3「AI が調べながら作る」の実体である
（`K/docs/memos/middle-draft/07-character-design.md:347-356`）。

## 7. GUI とボディ（前身 06）

### 7.1 ヘリがボディ ── 保護指定1

主人の言葉：最初はテキストのみ。ウィンドウのヘリなどを突っつくことで反応する。そこをボディの代わりにする（`K/docs/memos/方向性.md:14-16`）。

前身の最小の画面（`K/docs/memos/middle-draft/06-gui-and-body.md:219-241`、`K/docs/memos/middle-draft/04-unified-design.md:307-331`）：

```
┌─────────────────────────────────┐
│  [相棒の名前]                    │  ← 枠なしウィンドウ。ドラッグで移動
│                                  │
│  「こんにちは」                   │  ← セリフの表示
│                                  │
│  [入力欄_______________] [送信]  │  ← テキスト入力
│                                  │
│  ██████████████████████████████  │  ← ウィンドウの枠＝ボディ代わり
└─────────────────────────────────┘
         ↑ ここを突っつくと反応
```

主人の操作は4つ：入力して送信（対話）、突っつく（軽い返事やリアクション）、トレイから表示／非表示・設定・終了、ドラッグで移動。
相棒の側の表示は、セリフ、自律のつぶやき（ウィンドウ端に小さく）、状態の表示（ボディ画像が入ってから）。

**ボディが無くても人格と記憶は完全に動く**（`K/docs/memos/middle-draft/06-gui-and-body.md:241`）。

突っついた位置：前身は最初の段では位置を無視して「突っつかれた」という1種類の出来事として扱い、
後の段で位置から「頭を撫でた」「体をつついた」などの部位判定に使える余地を残した（`K/docs/memos/middle-draft/06-gui-and-body.md:178-184`）。

**食い違い（ヘリか全体か）**：主人の言葉は「ヘリ」（`K/docs/memos/方向性.md:15`）。前身の画面設計は「ウィンドウ本体をクリック」を突っつきとしている
（`K/docs/memos/middle-draft/04-unified-design.md:324`）。Utsushimi は主人の言葉に従い、**ヘリ（縁）を突っつく場所**とする。

### 7.2 表示の抽象

前身は GUI の実装を差し替えられるよう、表示を最小の口（6つ）に絞った
（`K/docs/memos/middle-draft/04-unified-design.md:62-75`、`K/docs/memos/middle-draft/06-gui-and-body.md:130-135`）。

| 口 | 役割 |
|---|---|
| 表示する / 隠す | ウィンドウの表示・非表示（常駐中は隠す） |
| セリフを出す | セリフ・吹き出しの更新 |
| ボディの状態を設定する | 待機・発話中・思考中・まばたき・休息（最初の段では何もしない） |
| 表示側で後から実行する | 裏の処理から表示へ安全に渡す唯一の窓口 |
| 突っつきを受ける | クリック（位置つき）の登録 |

ボディの状態の定義（`K/docs/memos/middle-draft/06-gui-and-body.md:157-170`）：待機（既定）、発話中（口パーツ差し替えの引き金）、
思考中（応答を作っている間）、まばたき（タイマーで自動）、休息（rest 欲求が高いとき）。

### 7.3 ボディの拡張口 ── PNGTuber 方式

PNGTuber は、リギングなしに複数枚の透過 PNG を切り替えてアバターを表す手法（最小4〜5枚：待機・発話・まばたき・発話中のまばたき）
（`K/docs/memos/middle-draft/06-gui-and-body.md:19-32`）。
前身は配信用の MotionPNGTuber そのものは採らず、**「レイヤー切り替え式の透過 PNG アニメーション」という概念だけを参考にする**とした
（`K/docs/memos/middle-draft/06-gui-and-body.md:51`）。
ビジュアルは後から足せる（`K/docs/memos/middle-draft/06-gui-and-body.md:60-61`）。

画像ボディを足す前提（`K/docs/memos/middle-draft/06-gui-and-body.md:243-255`）：表示の抽象があること、状態の定義が確定していること、
相棒が「発話中」を知らせられること。現実的な目標は「静止画＋口パーツ差し替えの口パク」まで。動画ループ合成の完全再現はさらに後。

### 7.4 前身での選定（記録のみ）

前身では主人のメモに「PythonGUI」とあり（`K/docs/memos/方向性.md:12`）、前身では tkinter を最初の GUI に採り、
per-pixel 透過が要る段で PyQt6 / PySide6 へ移る計画だった（`K/docs/memos/middle-draft/06-gui-and-body.md:285-287`）。
Utsushimi では技術選定を決め直す（`CLAUDE.md` §1）。ここは採用ではない。

## 8. キャラ（前身 07）

前身の設計でいちばん価値が高い部分。**全項目を中身つきで残す。**

### 8.1 3層パラメータモデル

キャラのパラメータを3層に分ける（`K/docs/memos/middle-draft/07-character-design.md:33-53`）。

| 層 | 前身での置き場 | 中身 | 変更 |
|---|---|---|---|
| 凍結核（Frozen Core） | persona_core.md | この子が「この子」であるための最小定義（C1〜C11） | 凍結後は不可（ユーザーの手動編集のみ） |
| 凍結殻（Frozen Shell） | style_samples.md | 核から導いた口調・反応の参照例（S1〜S7） | 凍結後は不可（ユーザーの手動編集のみ） |
| 可変層（Living Layer） | 記憶の DB と personality_trends.md | 経験とともに変わる部分（L1〜L6） | AI の自動更新（一部は承認制） |

この設計の基準は3つ：1対1・常駐・テキストで「この子はこの子だ」と感じさせるパラメータは何か／「根っこは変わらない」を技術で保証できる粒度／
ゆらぎを唯一性に変える仕組み（`K/docs/memos/middle-draft/07-character-design.md:21-27`）。

これは `CLAUDE.md` の禁則「人格の根っこ（凍結核）を AI が書き換えない。凍結後に変えられるのは主人の手だけ」の、前身での具体化である。

### 8.2 凍結核 C1〜C11（persona_core）

推奨合計 400〜800 文字（`K/docs/memos/middle-draft/07-character-design.md:81`）。表は `K/docs/memos/middle-draft/07-character-design.md:67-79`。

| # | パラメータ | 形式 | 推奨量 | 必須／任意 | 中身と設計根拠 | 出典 |
|---|---|---|---|---|---|---|
| C1 | 名前 | テキスト | 1〜20文字 | 必須 | 呼びかけの基本。名前は人格の象徴で、最も強い同一性の錨 | `K/docs/memos/middle-draft/07-character-design.md:69` |
| C2 | 一人称 | テキスト | 1〜5文字 | 必須 | 「僕」「私」「ワタシ」「吾輩」など。口調全体の基調を決める最重要要素 | `K/docs/memos/middle-draft/07-character-design.md:70` |
| C3 | 二人称（ユーザーの呼び方） | テキスト | 1〜20文字 | 必須 | 「マスター」「あなた」「おまえ」「〇〇さん」など。関係性の距離感を決める | `K/docs/memos/middle-draft/07-character-design.md:71` |
| C4 | 人格核文（コアステートメント） | 自然文 | 50〜150文字 | 必須 | この子が何者かを1〜2文で言う。例「好奇心旺盛だが臆病で、知らないことに出会うと興奮しつつも後ずさりする」 | `K/docs/memos/middle-draft/07-character-design.md:72` |
| C5 | 性格軸 | 構造化テキスト | 各軸20〜50文字 × 3〜5軸 | 必須 | 簡易性格モデル（§8.3）で書く | `K/docs/memos/middle-draft/07-character-design.md:73` |
| C6 | 口調パターン | テキスト | 50〜200文字 | 必須 | 語尾、敬語かタメ口か、特徴的な表現。例「〜だよね」「〜かもしんない」「えっとね、」 | `K/docs/memos/middle-draft/07-character-design.md:74` |
| C7 | 口癖 | リスト | 2〜5個 × 各10〜30文字 | 任意 | 繰り返し使う言い回し。例「ふむふむ」「それってさぁ」「まぁいっか」 | `K/docs/memos/middle-draft/07-character-design.md:75` |
| C8 | 年齢感／世代感 | テキスト | 10〜30文字 | 任意 | 数値ではなく印象。「高校生くらいの若さ」「老成した子供」など | `K/docs/memos/middle-draft/07-character-design.md:76` |
| C9 | 価値観／大切にしていること | 自然文 | 50〜150文字 | 必須 | 判断の基準軸。「正直であること」「楽しさ優先」「他者への思いやり」など | `K/docs/memos/middle-draft/07-character-design.md:77` |
| C10 | 禁忌／絶対にしないこと | リスト | 1〜3個 × 各20〜50文字 | 任意 | ネガティブな定義で輪郭をはっきりさせる。「嘘をつかない」「人を見下さない」など | `K/docs/memos/middle-draft/07-character-design.md:78` |
| C11 | 知識の自己認識 | テキスト | 30〜80文字 | 必須 | 「知らないことは素直に聞く」「知ったかぶりしがち」「知らないことが恥ずかしい」など | `K/docs/memos/middle-draft/07-character-design.md:79` |

なぜこの11項目か（`K/docs/memos/middle-draft/07-character-design.md:83-92`）：

- **C1〜C3**：テキストの相棒には見た目が無い。VTuber は外見で誰かわかるが、テキストでは名乗りと呼び方でしかわからない。呼称が同一性の最大要素になる
- **C4**：AITuber 設計の「キャラの芯を一文で決める」手法。性格軸（C5）の上位概念で、「このキャラならどう反応する？」の自己問答でいちばん参照される
- **C5**：Big Five の簡易版
- **C6〜C7**：「口調の参照例がいちばん安く効く人格維持の手段」という知見の裏付け。AITuber 設計でも「セリフ例を多めに与える」が最重視される。フィラー（つなぎ言葉）は C6 に含める（`K/docs/memos/middle-draft/07-character-design.md:419`）
- **C10**：禁止事項（ネガティブタグ）がキャラの一貫性を大きく上げる、という知見の直接の反映。別人格は禁忌の調整で生まれる（`K/docs/memos/middle-draft/07-character-design.md:417`）ので、禁忌がキャラの境界線を引く
- **C11**：デスクトップの相棒に固有。常駐して日常の話をする存在が「知らないことにどう反応するか」は、信頼関係に直結する

### 8.3 性格軸（C5）── 簡易性格モデル

Big Five は堅牢だが LLM への指示としては抽象的すぎ、特に協調性と外向性の制御が不安定とされる。
そこで、**対話で観測できる行動に直結する軸**に組み直した（`K/docs/memos/middle-draft/07-character-design.md:94-106`）。

| 軸 | 対応する Big Five | 定義 | 記述例 | 観測される行動 |
|---|---|---|---|---|
| 好奇心 | 開放性 | 未知に対する姿勢 | 「知らないことに飛びつく」／「慣れたものが好き」 | 新しい話題への反応、自分で調べる発火の傾向 |
| 社交性 | 外向性 | ユーザーとの距離感 | 「積極的に話しかける」／「聞かれたら答える」 | 自律発言の頻度、talk 欲求の閾値 |
| 繊細さ | 神経症傾向（反転） | 感情の振れ幅 | 「些細なことで動揺する」／「大抵のことは平気」 | 感情表現の強さ、ネガティブな反応の出やすさ |
| 几帳面さ | 誠実性 | 論理と秩序への志向 | 「正確さにこだわる」／「だいたいでいい」 | 情報を出すときの精度意識、曖昧な返答の許容度 |
| 思いやり | 協調性 | 相手（ユーザー）への配慮 | 「相手の気持ちを最優先」／「思ったことを言う」 | 批判的な意見の言い方、共感表現の頻度 |

各軸は**自然言語で20〜50文字**。数値スケールは採らない。理由は3つ：数値指示は LLM の行動への変換が不安定／自然言語の方が参照例を作るときに口調へ変換しやすい／
主人にとっても「好奇心: 8」より「知らないことに出会うとワクワクするけど、最初は遠巻きに様子を見る」の方が直感的
（`K/docs/memos/middle-draft/07-character-design.md:108-114`）。

### 8.4 凍結殻 S1〜S7（style_samples）

人格核から導いた**口調の参照実例集**。推奨合計 800〜1500 文字（17〜25例）（`K/docs/memos/middle-draft/07-character-design.md:116-130`）。

| # | 種別 | 推奨量 | 中身 | 出典 |
|---|---|---|---|---|
| S1 | 日常会話 | 3〜5例 × 各50〜100文字 | ふだんの雑談での反応 | `K/docs/memos/middle-draft/07-character-design.md:122` |
| S2 | 感情表現（喜） | 2〜3例 × 各30〜80文字 | 嬉しいとき、褒められたときの反応 | `K/docs/memos/middle-draft/07-character-design.md:123` |
| S3 | 感情表現（怒／不快） | 2〜3例 × 各30〜80文字 | 怒ったとき、嫌なことを言われたときの反応 | `K/docs/memos/middle-draft/07-character-design.md:124` |
| S4 | 感情表現（悲／寂） | 2〜3例 × 各30〜80文字 | 悲しいとき、寂しいときの反応 | `K/docs/memos/middle-draft/07-character-design.md:125` |
| S5 | 困惑／不知 | 2〜3例 × 各30〜80文字 | 知らないことを聞かれたとき、困ったときの反応 | `K/docs/memos/middle-draft/07-character-design.md:126` |
| S6 | ユーモア | 2〜3例 × 各30〜80文字 | 冗談を言うとき、ボケる／ツッコむときの反応 | `K/docs/memos/middle-draft/07-character-design.md:127` |
| S7 | 沈黙破り | 2〜3例 × 各30〜80文字 | 自律発言（つぶやき）のトーン。rest 欲求が高いときの口調の変化もここに含める | `K/docs/memos/middle-draft/07-character-design.md:128`、`K/docs/memos/middle-draft/07-character-design.md:503` |

作り方の原則（`K/docs/memos/middle-draft/07-character-design.md:132-137`）：

- **状況と発話を対にする**。例「（ユーザーに褒められて）え、えへへ...そう？ ほんとに？ ...ありがと。」
- **感情の幅を見せる**。同じ喜びでも小さいものと大きいものの両方
- **禁忌と整合させる**。C10 に触れる例は入れない
- **ユーモアの方向を絞る**。ダジャレ／皮肉／天然ボケ／ツッコミのうち、人格核文（C4）と合うものだけ

凍結後も本体は書き換えない。新しい口癖は傾向メモの補足欄（supplementary_styles）に承認制で**足すだけ**
（`K/docs/memos/middle-draft/07-character-design.md:226-236`）。

### 8.5 可変層 L1〜L6

「根っこ以外が変わる」の具体的な定義（`K/docs/memos/middle-draft/07-character-design.md:139-150`）。

| # | パラメータ | 前身での置き場 | 変更の主体 | 変更の頻度 | 中身 | 出典 |
|---|---|---|---|---|---|---|
| L1 | 興味の広がり | 興味の記録（curiosity_targets） | AI 自動 | 日〜週 | 「最近ビザンツ帝国について調べた」など。自分で調べた結果が積もる | `K/docs/memos/middle-draft/07-character-design.md:145` |
| L2 | 関係性の深度 | 傾向メモ（personality_trends） | AI が提案 → 主人が承認 | 週〜月 | 「最近ユーザーとゲームの話で盛り上がることが多い」などの傾向の認識 | `K/docs/memos/middle-draft/07-character-design.md:146` |
| L3 | 話題の詳しさ（知識の蓄積） | 日記＋会話断片 | AI 自動 | 日 | 会話で得た**事実知識**。「ユーザーに教えてもらった〇〇のこと」。「このキャラがどの話題に詳しいか」を判定する土台 | `K/docs/memos/middle-draft/07-character-design.md:147` |
| L4 | エピソード記憶（体験の蓄積） | 会話断片 → 日記 | AI 自動 | リアルタイム〜日 | **出来事そのもの**。「あの時こう言ったよね」「昨日一緒に〇〇の話をした」。L3 は「何を知っているか」、L4 は「何を経験したか」 | `K/docs/memos/middle-draft/07-character-design.md:148` |
| L5 | 感情の傾向変化 | 傾向メモ（personality_trends） | AI が提案 → 主人が承認 | 月 | 「最近少し打ち解けてきた」など。性格軸（C5）そのものは変えず、表出のニュアンスが変わる | `K/docs/memos/middle-draft/07-character-design.md:149` |
| L6 | ユーザーモデル | ユーザー情報（human_block） | AI の自己編集 | 随時 | 主人の好み・話題・生活パターンの認識（歯止めは §4.4） | `K/docs/memos/middle-draft/07-character-design.md:150` |

成長の仕組み（`K/docs/memos/middle-draft/07-character-design.md:195-236`）：

- **L1**：好奇心が発火 → 自分で調べる → 興味の記録に派生元つきで残す → 関連する話題が出たら思い出す
- **L2**：日記が積もる → 一定期間ごとに傾向を分析 → 傾向メモへ提案 → 主人が承認して反映 → 対話の調子に効く。
  承認制にするのは、「打ち解けてきた」と AI が判断しても主人はそう思っていないかもしれず、自動にすると「勝手に馴れ馴れしくなった」不快につながるから
  （`K/docs/memos/middle-draft/07-character-design.md:224`）
- **新しい口癖**：会話断片で特定のフレーズの頻度が閾値を超える → 口癖候補として提案 → 承認後に補足欄から参照。参照例の本体は変えない

**食い違い（前身の内部）**：L2 の反映先を、前身は流れ図で「Warm Memory として注入」と書き（`K/docs/memos/middle-draft/07-character-design.md:221`）、
層の関係の節では傾向メモを Hot としている（`K/docs/memos/middle-draft/07-character-design.md:58`）。前身の他の文書も Hot で揃っている
（`K/docs/memos/middle-draft/04-unified-design.md:245`）ので、本書は **Hot（毎回入る）** と読む。

### 8.6 凍結と可変の境界

**凍結すべきもの＝「この子」を「別の子」と区別する最小の要素**（`K/docs/memos/middle-draft/07-character-design.md:152-172`）。

判断の3テスト：

1. **同一性テスト**：変わったら「別人」に感じるか → Yes なら凍結
2. **逆転テスト**：逆になったら矛盾を感じるか → Yes なら凍結
3. **時間テスト**：現実の人間でも数年で変わりうるか → Yes なら可変

| 対象 | 同一性 | 逆転 | 時間 | 判定 |
|---|---|---|---|---|
| 名前 | 変わったら別人 | ── | 変わらない | **凍結** |
| 一人称 | 変わったら違和感大 | ── | まれに変わる | **凍結** |
| 口調の基調 | 別人感が出る | 敬語とタメ口の入れ替わりは大変化 | 変わりにくい | **凍結** |
| 好奇心の方向性 | 同じ子でも興味は変わる | ── | 変わる | **可変** |
| 好きな話題 | 増えても自然 | ── | 変わる | **可変** |
| ユーザーへの態度 | 深まるのは自然 | ── | 変わる | **可変**（承認制） |
| 口癖の追加 | 自然に増えうる | ── | 変わる | **一部可変**（C7 は凍結、新しい口癖は傾向メモに承認制で追記） |

### 8.7 権限マトリクス ── 保護指定4

主人の言葉：ユーザーが書ける部分と書けない部分をどう変えるかは重要（`K/docs/memos/2026-03-03-char.md:10`）。

前身の権限マトリクス（`K/docs/memos/middle-draft/07-character-design.md:242-253`）。行の名前は前身での名前。
前身では会話断片・日記・興味の記録を1つの DB のテーブルに置き、それ以外を個別のファイルにした。

| 前身での置き場 | ユーザー読取 | ユーザー書込 | AI 読取 | AI 書込 | タイミングの制約 |
|---|---|---|---|---|---|
| persona_core（凍結核 C1〜C11） | 常時 | 凍結前：自由／凍結後：手動編集のみ | 常時 | 凍結前のみ | ウィザード中か凍結前 |
| style_samples（凍結殻 S1〜S7） | 常時 | 凍結前：自由／凍結後：手動編集のみ | 常時 | 凍結前のみ | ウィザード中か凍結前 |
| human_block（L6） | 常時 | 常時 | 常時 | 常時（自己編集） | ── |
| personality_trends（L2・L5・口癖候補） | 常時 | 常時 | 常時 | 提案のみ（承認待ち） | ── |
| 設定ファイル | 常時 | 常時 | 常時 | 不可 | ── |
| observations（会話断片、L4） | 記憶閲覧機能で（前身 Phase 2 以降） | 不可 | 常時 | 常時 | ── |
| day_summary（日記、L3・L4） | 記憶閲覧機能で（前身 Phase 2 以降） | 不可 | 常時 | 常時 | ── |
| curiosity_targets（興味の記録、L1） | 記憶閲覧機能で（前身 Phase 2 以降） | 不可 | 常時 | 常時 | ── |

前身では、DB の中身を主人が見る手段は Phase 1 では外部ツールで直接開くこと、Phase 2 以降で画面内の記憶閲覧（日記一覧・検索）とした
（`K/docs/memos/middle-draft/07-character-design.md:255`）。

領域でまとめると（`K/docs/memos/middle-draft/07-character-design.md:178-192`）：凍結領域＝凍結核・凍結殻／AI が自分で編集できる領域＝ユーザー情報・会話断片・日記・興味の記録／
承認制の領域＝傾向メモ。

線引きの根拠（`K/docs/memos/middle-draft/07-character-design.md:257-275`）：

- **主人が書くべきもの**：ユーザー情報（自分のことは本人がいちばん正確に知っている）、凍結前の人格核（「どんな子が欲しいか」は主人の願いで、AI は補完・整形する役）、傾向メモの承認（関係の変化は主人が「そうだ」と感じて初めて有効）
- **主人が書けないもの**：会話断片と日記（AI の知覚に基づく。書き換えると記憶の整合が崩れる）、興味の記録（キャラの好奇心の軌跡。主人が操作すると「自分から調べた」体験が嘘になる）
- **凍結後の人格核を「手動編集のみ」にする理由**：プログラムからの書込を禁じて AI の自己改変（人格ドリフト）を物理的に防ぐ。一方で主人がエディタで直接変えることは許す。「主人は自分の相棒の根っこを変える権利がある」という思想。変えた場合は次の起動で「変更されました。再凍結しますか？」と確かめる

凍結の状態は設定で持ち、手動編集を検出したら再凍結を確かめる（`K/docs/memos/middle-draft/04-unified-design.md:213-219`）。
傾向メモへのプログラムからの書込は禁止で、AI は提案だけ行い、主人が承認して初めて反映される。最初の段では対話の中で提案を見せ、主人が「承認」と返すと追記する
（`K/docs/memos/middle-draft/04-unified-design.md:221-227`）。

### 8.8 最初の起動 ── 主人と AI の分担（ウィザード3方式）

3方式の流れ（`K/docs/memos/middle-draft/04-unified-design.md:187-193`）：

| 方式 | 流れ |
|---|---|
| A：AI おまかせ | キーワード入力 → AI が3案 → プレビュー会話 → 選ぶ → 凍結 |
| B：既存イメージ | 主人が自由に書く → AI が整形・補完 → プレビュー会話 → 凍結 |
| C：白紙育成 | 最小限（名前＋一人称）→ 20会話後に AI が提案 → 承認 → 凍結 |

パラメータ単位の分担（`K/docs/memos/middle-draft/07-character-design.md:277-312`）。

**方式A（AI おまかせ）**（`K/docs/memos/middle-draft/07-character-design.md:281-296`）

| パラメータ | 主人の入力 | AI の生成 |
|---|---|---|
| C1 名前 | キーワード（「和風」「かわいい」など） | 3候補を示す |
| C2 一人称 | ── | 名前・性格から導く |
| C3 二人称 | 呼ばれたい名前（任意） | 既定の候補 |
| C4 人格核文 | キーワード2〜3個（「元気」「内向的」など） | 全部生成 |
| C5 性格軸 | ── | C4 から導く |
| C6 口調 | 好みの口調サンプル（任意） | 全部生成 |
| C7 口癖 | ── | 全部生成 |
| C8 年齢感 | 希望（任意） | 既定を生成 |
| C9 価値観 | ── | C4 から導く |
| C10 禁忌 | ── | C4・C9 から導く |
| C11 知識の自己認識 | ── | C4・C5 から導く |
| S1〜S7 | ── | 全パラメータから生成 |

**方式B（既存イメージ）**（`K/docs/memos/middle-draft/07-character-design.md:298-303`）：C1〜C11 は主人が自由に（全部書いてもよい）書き、AI は足りない分を補完・整形する。S1〜S7 も主人が会話例を書いてよく、AI はそれを参考に不足分を作る。

**方式C（白紙育成）**（`K/docs/memos/middle-draft/07-character-design.md:305-312`）：C1 名前と C2 一人称は主人が必ず書く。C3〜C11 は20会話の後に AI が全体像を提案する。S1〜S7 は提案が承認されてから作る。

これが保護指定3「最初の人格や癖のうち、主人が書いた部分以外は、AI が調べながら作る」の、前身での具体化である（主人の言葉は `K/docs/memos/方向性.md:17`）。

### 8.9 生成時のゆらぎ ＝ 唯一性 ── 保護指定3

主人の言葉：ユーザーが同じ内容を入力しても、生成 AI がネットなどで調査し作っていく過程でゆらぎが出るはず。これを唯一無二の存在にするのだと思う（`K/docs/memos/2026-03-03-char.md:11`）。

ゆらぎは2種類ある。LLM 固有のゆらぎ（確率的な選択のばらつき）と、**情報環境のゆらぎ**（検索結果・検索の時機・キーワードの組み合わせの違い）。
後者の方が豊かで意味のあるゆらぎを生むので、**意図的に設計へ組み込む**（`K/docs/memos/middle-draft/07-character-design.md:316-328`）。

生成の5段と、各段に埋めたゆらぎ（`K/docs/memos/middle-draft/07-character-design.md:330-368`）：

1. **入力の解釈**：例「元気で歴史好きな女の子」。「元気」の解釈の幅（快活／天真爛漫／体育会系／ハイテンション…）がゆらぎ1
2. **連想の拡張（最大のゆらぎ源）**：関連する要素を5〜7個挙げさせる。連想の向きが毎回違う（ゆらぎ2）。例A「朝型・声が大きい・走るのが好き」／例B「笑い上戸・負けず嫌い・泣き虫だけど立ち直りが早い」
3. **調査（情報環境のゆらぎ）**：連想から1〜2語で Web を調べる。結果は日時や検索エンジンの状態で変わる（ゆらぎ3）。例A たまたまビザンツ帝国の記事 →「東ローマ帝国に詳しい子」／例B たまたま戦国時代の記事 →「真田幸村が推しの子」。自分で調べる仕組みが無い段では LLM の内部知識だけで具体化する（ゆらぎは弱いが存在する）
4. **統合**：1〜3 をまとめて C1〜C11 を作る。取捨選択がゆらぎ4
5. **参照例の生成**：C1〜C11 から S1〜S7 を作る。同じ性格でも口調が微妙に違う（ゆらぎ5）。例A「ねぇねぇ、知ってる？ ビザンツ帝国ってさぁ...」／例B「あのねっ、幸村ってほんとすごいんだよ！」

ゆらぎを調える設定（`K/docs/memos/middle-draft/07-character-design.md:370-378`）：連想の数（既定5、多いほどゆらぐ）、生成時の温度（既定0.9。通常会話は0.7程度）、
方式A で示す候補数（既定3）、Web 調査の有無と検索キーワード数（調べる仕組みが入ってから足す）。

**記録と再現不能性**（`K/docs/memos/middle-draft/07-character-design.md:380-396`）：生成日時・使ったモデル・連想の結果・検索クエリ・検索で拾った要点・方式を、人格核の先頭にメタデータとして残す。
ただし**乱数の種や乱数の状態は意図的に残さない**。メタデータは「この子がどう生まれたか」の記録であって、再現のためのレシピではない。主人が後から「この子はこういう経緯で生まれた」と振り返るためのもの。

**なぜ唯一性になるか**（`K/docs/memos/middle-draft/07-character-design.md:398-406`）：スライダー式のキャラメーカーでは同じ設定なら同じキャラになる。ここでは、連想の拡張が LLM の内部状態に依存して分かれ、
Web 調査で時間的に一回きりの情報が混ざり、統合時の取捨が確率的に決まる。この3つが掛け合わさって、同じキーワードからでも毎回違うキャラが生まれる。
「この世に同じ人間がいない」ことの計算による再現であり、前身の最も重要な設計意図の1つ。

**Utsushimi での補足**：`CLAUDE.md` の禁則は「ただしテストでは、ゆらぎを外から固定して再現できるようにする」と定めている。
前身の「種を**記録しない**」は本番の個体の再現を不能にするためのもので、テストで種を**外から与える**ことと矛盾しない。両方を満たす。

### 8.10 VTuber / AITuber からの知見

前身が調べて取り込んだもの（`K/docs/memos/middle-draft/07-character-design.md:410-422`）：

- 感情の表し方を独立して持つのは有効 → 参照例を感情別に分ける（S2〜S5）
- 別人格は禁忌の調整で生まれる → 禁忌（C10）は人格の輪郭に本質的
- 見かけの自律性は開発者の手動調整で支えられている → 最初は自動の一貫性チェックに頼りすぎず、主人の承認制を併用する
- セリフ例を多めに与えることが最重要、フィラーを設定する → 参照例（S1〜S7）を最優先で充実させ、フィラーは口調（C6）に含める
- 基本設定／深層／表層の3層プロンプト → 人格核を文脈に入れるときに階層を意識する
- 人格軸を一文で定義＋性格タグ＋感情レンジ → 人格核文（C4）に直接反映。感情レンジは欲求システムの発現制御に応用できる
- AI VTuber の魅力は予測不能性と人間との協働。技術的な不完全さが個性として受け入れられる → 不完全さを消さず個性として生かす。傾向メモの承認制は主人との共同構築にあたる

キャラ崩壊の防止策の翻訳（`K/docs/memos/middle-draft/07-character-design.md:424-435`）：

| VTuber / AITuber の手法 | 相棒での対応 |
|---|---|
| バックストーリーの固定 | 人格核の凍結 |
| 口調の統一（台本・サンプル） | 参照例を毎回入れる |
| NG ワード・NG 行動 | 禁忌（C10）＋禁止の指示 |
| 配信中の裏方の介入 | 応答前の簡易自己問答（§5.1 原則4） |
| 定期的なキャラ確認 | 10〜20メッセージごとの整合性チェック（§5.1 原則5） |
| 視覚デザインと性格の一致 | テキストでは口調が「見た目」にあたる。C6 と C4 を整合させる |

### 8.11 1対1・テキスト主体・常時起動に固有のこと

**1対1**（`K/docs/memos/middle-draft/07-character-design.md:478-484`）：二人称（C3）の重みが大きい（名前で呼ばれる親密さはテキストでは絶大）。
主人のことを覚えていること（ユーザー情報）が関係の実感になる。毎日1対1で話すので関係は配信より早く深まり、関係性の深度（L2）の更新頻度を適切にする必要がある。

**テキスト主体**（`K/docs/memos/middle-draft/07-character-design.md:486-497`）：音声も映像も無いので、口調が人格のすべてを担う。
「...」「！」「っ」「〜」などの装飾文字の使い方も口調（C6）に含める。句読点・改行の癖（短文を連ねるか、長文で語るか）も個性。
**括弧書きの心情描写（「（嬉しそうに）」）は使わず、文体と語彙だけで感情を表す**。理由：相棒は「話し相手」であって「小説の登場人物」ではない／括弧書きは第三者の視点で1対1の没入を損なう／口調が豊かなら文体だけで感情は伝わる。
前身はこれを確定としていた（`K/docs/memos/middle-draft/04-unified-design.md:407`）。

**常時起動**（`K/docs/memos/middle-draft/07-character-design.md:499-505`）：rest 欲求が高いときの口調の変化を参照例（S7）に含める。
時間帯の挨拶は人格核に書かず、応答を作るときに現在時刻を渡して対応する。毎日会う存在なので、「今日は元気がない」「今日はいつもより話しかけてくる」といった日ごとの揺れがあると自然で、これは欲求の自然な変動で出す。

### 8.12 前身が残したキャラの未決事項

（`K/docs/memos/middle-draft/07-character-design.md:570-578`）

- 感情レンジを数値で持つか（欲求システムと連携して感情の「既定の比率」を持たせるか）
- 人格核の書式
- 参照例の最適な例数（17〜25は推奨値。少なすぎて崩れる／多すぎて文脈を圧迫する境目を実際に確かめる）

- 方式C の凍結の時機（20会話は仮の値。少なすぎれば不完全、多すぎれば凍結前に馴染みすぎる）
