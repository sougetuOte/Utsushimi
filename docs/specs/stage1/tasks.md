# 段1「そばにいて、話せて、覚えている」── tasks

**1タスク＝1フェーズ＝1委譲単位。**上から順に行う。各タスクは G0（`goal.md`）から入り、検収役の検収を通して閉じる。
**T1 で実起動できる本体ができ、T2 以降はその本体に足す。**部品だけで閉じるタスクは無い（`docs/lessons.md` §4「統合を最後に回して、止まった」）。
何を作るかは `requirements.md`、どう作るかは `design.md`。完了条件の元は `docs/lessons.md`（項目番号を併記する）。

**全タスクに共通の完了条件**（各タスクの goal.md に写す）：

- 完了条件：そのタスクで足したふるまいを、実起動した本体で1つずつ実際に起こして、反応があった（§4「突っつきに反応しない（配線漏れ）」）。
- 完了条件：そのタスクで足したふるまいの確かめ方を `docs/smoke-test.md` に足し、その項目を実起動で通した日付と結果が報告に書かれている（B-10）。
- 完了条件：画面に関わる変更をしたタスクでは、実起動してその画面を目で確かめ、はみ出し・重なり・操作できない部分が無かったことが報告に書かれている（L-5）。

- [ ] **T4 覚えている ── 昔の話を引き、日記を書き、文脈を保つ**

  - 完了条件：ある日に話した話題について、1日の区切りをまたいだ後に実起動して「この前の〇〇の話」と振ると、その中身に触れた返事が来て、ログに検索で引いた昔の発言の番号が残っていた（BH-14）。

- [ ] **T5 終わる ── どの経路でも1回だけ終わり、2回目に続きから始まる**
  終了処理の1か所化（1回目だけ進む）、段1の終了の全経路（トレイ・キャラ作りの画面を閉じる・コンソールでの中断・Windows のセッション終了）、

  - 完了条件：実起動して対話し、トレイから終了して、終了処理の開始と完了がログにそれぞれ1回だけ記録されていた（Bug-4）。
  - 完了条件：段1にある終了のしかたごとに実起動→対話→終了を行い、どの経路でも終了処理がログに1回だけ記録され、次の実起動で直前の会話が残っていた（L-3・BH-16）。
  - 完了条件：実起動して、トレイから終了した直後に起動したコンソールで中断しても、終了処理がログに1回だけ記録された（B-9）。
  - 完了条件：同じ日のうちに、同じデータのまま「実起動→対話→終了」を2回続けて行い、2回目の終了でもエラーが出ず、その日の日記が失われも重複もしていなかった（Bug-5）。
  - 完了条件：前の起動で対話して終了したデータを残したまま2回目を実起動し、エラーなく起動して、前回の会話の中身に触れた発言が出た（L-2）。

- [ ] **T6 主人について・関係の変化・点検 ── 根っこ以外が歴史で変わる入口**
  主人についての更新判断と履歴、「自分について…」の小窓、関係の変化の提案と承認・見送り、人格のぶれの定期点検。どれも返事の後に裏で動く。

  - 完了条件：実起動して「自分について…」の小窓から項目を足せ、会話の記録と日記を書き換える操作は画面のどこにも無かった（BH-20）。
  - 完了条件：実起動して、関係の変化の提案が欄に「承認／見送る」つきで出て、「見送る」では何も加わらず、「承認」では傾向の記録に1件加わり、次の返事の文脈に入っていた（ログ）。終了後、人格のファイルのハッシュは固めた時と同じだった（BH-22・BH-19）。
  - 完了条件：実起動して点検の間隔を超えて話すと、ログに点検の実行と結果が1回記録され、ぶれありのときは次の文脈に直しの指示が入っていた（BH-23）。
  - 完了条件：実起動して3往復以上対話し、そのあいだ裏の更新判断・提案の判断も動いた状態で、次の入力への返事が待たされずに返り、ログにエラーが1件も無かった（Bug-2・L-1）。
