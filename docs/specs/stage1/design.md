# 段1「そばにいて、話せて、覚えている」── design

**どう作るか。**何を作るかは `requirements.md`、作る順は `tasks.md`。
技術の前提は ADR 0001〜0004。キャラの体系（C1〜C11・S1〜S7・L1〜L6・権限）は `docs/concept.md` §8 をそのまま使い、ここに写さない。
BH 番号は `docs/behaviors.md`。

## 1. 全体の形

```
┌──────────── 画面のスレッド（Qt） ────────────┐        ┌──────────── 核のスレッド（asyncio） ────────────┐
│ 会話の窓（枠なし・ヘリ・欄・入力）            │  値 →  │ 会話：受け取る→保存→文脈を組む→LLM→保存         │
│ キャラ作りの画面                              │ ────→  │ キャラ作り：連想→調べる→候補→お試し→確定         │
│ トレイ（表示・隠す・最前面・自分について・終了）│ call_soon_threadsafe │ 記憶：SQLite（接続はここだけ）          │
│ 知らせ・確かめの小窓                          │  ←──── │ 人格：テキストファイルを読む（書く口は確定だけ）  │
└──────────────────────────────────────────────┘ Qt シグナル │ メインループ：行動予定の見回り（1秒ごと）       │
                                                            │ 終了：1か所の終了処理（1回だけ）                │
                                                            └───────────────────────────────────────────────┘
```

- スレッドは2本だけ（ADR 0004）。**SQLite の接続・LLM のクライアント・人格のファイルは核だけが触る。**
  画面は核に「値」（文字列・小さな dict）を渡し、核は画面に Qt シグナルで値を返す。物（接続・オブジェクト）は渡さない。
- パッケージは1つ（`utsushimi`）。中は `ui`（画面）・`core`（核の入口・会話・メインループ・終了）・`memory`（SQLite）・
  `persona`（人格のファイル）・`creation`（キャラ作り）・`llm`（LLM の口）に分ける。**分けるのはここまで**（迷ったら足さない）。
- 起動：`pythonw.exe -m utsushimi`（uv の venv、Python 3.14。ADR 0001）。主人の起動方法はこれを指すショートカット（Bug-1）。

## 2. データの置き場

すべて `data/` の下（git に載せない。D6）。

| 物 | 形 | 書く者 | 読む者 | 対応 |
|---|---|---|---|---|

| `data/persona/style.md` | Markdown。見出し `## S1 日常会話` 〜 `## S7 沈黙破り`、各例は「（状況）発話」 | 同上 | 核 | S1〜S7・BH-19 |
| `data/persona/origin.md` | Markdown。生まれた経緯（日時・モデル・方式・連想・調べた語と要点）。**乱数の種は書かない** | 確定のときの核だけ | 主人 | BH-10・BH-11 |
| `data/utsushimi.db` | SQLite（WAL・`synchronous=FULL`・1発言1コミット。ADR 0002） | 核 | 核 | 下表 |
| `data/config.toml` | 主人の設定（最前面・連想の数・文脈の上限・点検の間隔・1日の区切りの時刻・LLM の呼び先とモデル ID・effort） | 主人（最前面は画面からも） | 核・画面 | BH-02・BH-37・BH-41 |
| `data/logs/utsushimi.log` | 1行1出来事（時刻・種類・値） | 両スレッド（ログの仕組みはスレッドをまたいでよい） | 主人・検収 | lessons の「ログで数える」 |

`config.toml` が無ければ、リポジトリの `config.default.toml`（git に載る。秘密を持たない）を写して作る。

SQLite の表（段1で要るものだけ）：

| 表 | 中身 | 層 | 対応 |
|---|---|---|---|
| `utterances` | 1発言1行（時刻・話者・本文・種類＝対話／突っつき／お試し） | L4 | BH-01・BH-13 |
| `utterances_fts` | `utterances` の本文の FTS5（trigram） | — | BH-14 |
| `diaries` | 1日1行（日付・本文・作った時刻）。**日付に一意制約**（同じ日を2度作らない） | L3・L4 | BH-15・Bug-5 |
| `master_facts` ／ `master_facts_history` | 主人について（項目・値・出どころ＝主人が書いた／会話から）と、その変更の履歴 | L6 | BH-18・BH-20 |
| `trends` ／ `trend_proposals` | 承認された関係の変化（L2・L5・口癖候補）と、提案（承認／見送り／保留） | L2・L5 | BH-22 |
| `persona_seal` | 凍結した時刻と、`core.md`・`style.md` の SHA-256 | — | BH-19・BH-21 |
| `lifecycle` | 起動と終了の記録（開始・完了・経路） | — | BH-16・Bug-4 |

**書く口の形で権限を担保する**（`docs/concept.md` §8.7）：`memory` は `utterances`・`diaries` を「足す」口だけを持ち、書き換える口を持たない。
画面には会話の記録と日記を書き換える操作を置かない（BH-20）。`persona` の書く口は `seal(draft)` の1つだけで、
`persona_seal` に行があれば書かずに拒む（凍結後に AI が根っこを書き換えられない。BH-19）。

## 3. 画面

- **会話の窓**：枠なし、既定 570×390（前身が主人の感想で 1.5 倍にした大きさ。BH-02 の備考）。外周 8px の縁がヘリ、
  その内側に上の帯（名前と「×」）・やり取りの欄（折り返し・縦スクロール）・入力行。スパイクの配置（`spikes/README.md`）と同じ。
  - 上の帯をドラッグで移動（BH-02）。窓の位置は終了時に `config.toml` に残す。画面の外に出た位置は、次の起動で画面の中に戻す（B-11）。
  - やり取りの欄は、長い返事でも欄の中でスクロールし、入力行は常に見えて押せる（Bug-3）。
  - **タスクバーに出さない**（Qt のツール窓）。入口はトレイ。前身の「最小化」は「隠す」に畳む（BH-03）。
  - 「×」と Alt+F4 は隠すだけ（BH-03）。終了はトレイの「終了」から。
- **トレイ**：左クリックで表示／隠すの切り替え。メニューは「表示」「隠す」「最前面」（チェック。BH-02）「自分について…」（BH-20）「終了」。
- **キャラ作りの画面**（`data/persona/` に人格が無いとき、会話の窓の代わりに出る。BH-06）：方式を選ぶ → 入力 → 経過の表示 →
  候補3体（名前・人格核文。BH-42）→ お試しの会話（BH-08）→「確定」／「やり直す」。確定したら同じプロセスのまま会話の窓に替わる（前身の再起動を無くす）。
  設定ファイルもコマンドも要らない。始めから確定まで画面の上だけで終わる（BH-09）。
- **知らせ・確かめの小窓**：人格のファイルが壊れている（BH-25）／手で変えられた（BH-21）／関係の変化の提案（BH-22。欄の中のカードでもよい）。
- **ヘリの突っつき**：アプリ全体のイベントフィルタで押された位置を窓の座標に直し、縁なら「突っつき」として核へ渡す。内側は普段どおり（S2 で実測済み。保護指定1）。

## 4. 流れ

### 4.1 起動

1. 画面のスレッドで2重起動を確かめる（名前つきのローカルサーバー。先に起動しているものがあれば、それに「表示」を頼んで自分は終わる）。
2. 核のスレッドを起こす。核は `lifecycle` に起動を記録し、前回の終了が記録されていなければ「前回は正しく終わらなかった」とログに残す。
3. 人格を読む。無ければキャラ作りへ（BH-06）。壊れていれば知らせの小窓を出し、閉じたら終了する（BH-25。必須の見出しと、中身が空でないことを見る）。
   `persona_seal` のハッシュと違えば、知らせて「この内容で固め直す／このまま使う」を問う（BH-21。固め直すのは主人の選択で、ハッシュを更新する）。
4. 日記の欠けを埋める：`utterances` に発言があって `diaries` に無い日（今日を除く）を古い順に作る（BH-15）。**画面は先に出し、欠け埋めは裏で**行う。
5. 直近5日の日記を Warm として読み（BH-14）、会話の窓を出す。起動の時刻帯を最初の文脈に入れる（Bug-7）。

### 4.2 対話（BH-01・BH-13・BH-14・BH-17・BH-23・BH-24）

1. 画面は入力を核へ渡す。核は**まず `utterances` に1行足してコミット**し、それから行動予定をすべて非活性に戻して走っている行動予定の仕事を取り消す（保護指定2・BH-29 の口）。
2. 文脈を組む。**順番は固定**し、変わらない物を前に置いてプロンプトキャッシュを効かせる（ADR 0003）：
   1. 固定の指示（キャラとして話す・気持ちを括弧書きで書かない（BH-24）・返事の前に「このキャラならどう反応するか」を踏まえる（BH-23））
   2. 人格の根っこ（`core.md`）と口調の見本（`style.md`）── **ここまでをキャッシュの区切りにする**
   3. 主人について（L6）・承認された関係の変化（L2・L5）
   4. 直近の日記（Warm）・検索で引いた昔の発言（Cold。FTS5 で上位5件）
   5. 今の時刻と日付（Bug-7）・点検の直し（あれば）
   6. 今日の会話（古い順）
3. 上限（`config.toml` の文字数）を超えるときは、**4 の昔の発言 → 4 の日記 → 6 の古い方**の順に削り、1〜3 は削らない（BH-17）。削った物と量をログに残す。
4. LLM を**ストリーミング**で呼び、届いた分から欄に出す（BH-04）。送信から最初の文字までの秒数をログに残す。
   過去の返事は本文の文字だけを渡し、思考のブロックは渡さない（ADR 0003 の「履歴を書き換えない」は、渡した思考ブロックに掛かる。渡さなければ削っても触れない ── **未測。T4 で確かめる**。§9）。
5. 返事を `utterances` に足してコミットする。返事が `refusal` で終わったら、本文の代わりに「うまく返せなかった」旨を欄に出し、ログに残す。
6. 返事の後、**裏で**（主人の次の入力を待たせずに）：主人についての更新判断（4.4）、関係の変化の提案の判断（4.5）、発言数が点検の間隔に達していれば人格のぶれの点検（BH-23）。
   ぶれありなら、次の文脈の 5 に直しの指示を1回入れる。

### 4.3 キャラ作り（BH-07〜BH-11・BH-41・BH-42。保護指定3）

`docs/concept.md` §8.8〜§8.9 の5段をそのまま使う。

| 段 | 中身 | ゆらぎ |
|---|---|---|
| 1 入力の解釈 | おまかせ：キーワード2〜3個／既存イメージ：主人の自由な記述 | LLM |
| 2 連想の拡張 | 連想を多めに出させ、**核の乱数**で `config.toml` の数（既定5。BH-41）だけ選ぶ | LLM ＋ 核の乱数 |
| 3 調べる | 選んだ連想から**核の乱数**で1〜2語を選び、サーバー側の web search で調べ、要点を拾う（BH-11） | 核の乱数 ＋ 検索の時機 |
| 4 統合 | 1〜3 から C1〜C11 を作る。おまかせは3体（BH-42）、既存イメージは主人の記述を整えて足りない所を補う1体 | LLM |
| 5 見本 | C1〜C11 から S1〜S7 を作る（17〜25例） | LLM |

- 候補を選ぶとお試しの会話（本物の対話と同じ文脈の組み方。発言は種類＝お試しで残す）。「やり直す」は段2から、「確定」は `persona.seal()`（BH-08）。
- 確定で `core.md`・`style.md`・`origin.md` を書き、`persona_seal` にハッシュを残す。**乱数の種は、どこにも書かない**（`docs/concept.md` §8.9）。
- **核の乱数は外から与えられる**：`creation` は乱数の生成器を引数で受け取る。本番は OS の乱数で作り、テストでは種を固定したものを渡す（禁則。§6）。
- LLM は思考を切れず、温度も渡せない（ADR 0003）。LLM のゆらぎは止めない。止めるのはテストのときだけで、LLM の口を偽物に替えて行う（BH-37）。

### 4.4 主人について（BH-18・BH-20）

- 返事の後、低い effort で「主人の属性が**はっきり**言われたか」を構造化出力（項目・値・根拠の発言）で判定させる。推測・その場限り・無しなら何もしない。
- 書くときは、同じ項目の古い値を `master_facts_history` に移してから新しい値で上書きする（新しい方が勝つ。消すことはしない）。
- 主人は「自分について…」の小窓で項目を足し・直せる。出どころは「主人が書いた」になる。

### 4.5 関係の変化（BH-22。保護指定4）

- 返事の後、低い effort で、日記と今日の会話から「関係の変化の候補」があるかを判定させる（多くても1日1件。うるさくしない）。
- 候補は `trend_proposals` に保留で足し、欄に「承認／見送る」つきのカードで出す。**承認で初めて `trends` に足す**（AI は提案だけ）。
- 呼び方（C3）は根っこなので、ここでは扱わない（BH-39 は主人の判断待ち）。

### 4.6 日記（BH-15）

- 作るのは3つの時：終了のとき（その日の分）、起動のとき（欠けた日の分）、**起動したまま日付をまたいだとき**（前の日の分。メインループの行動予定。4.7）。
- 1日分の発言から、キャラの視点で5〜8文。`diaries` は日付に一意なので、同じ日を2度作ろうとしたら作らない（Bug-5）。
- 1日の区切りの時刻は `config.toml` に置く（既定 00:00）。日付またぎは、これを数分先にして実起動で確かめる（Windows の時計は触らない）。
- 終了のときの日記は、窓とトレイを先に消してから作り、上限（既定60秒）を超えたら作らずに終える。作れなかった日は次の起動で埋まる。

### 4.7 メインループ（保護指定2）

- 核の中の常駐タスク。1秒ごとに回り、**止まらない**。やることは行動予定の活性の計算と、活性な行動予定の実行の判定だけ。**活性の計算に LLM を呼ばない**（BH-26）。
- 行動予定は「活性の条件」と「やる仕事」の組。段1の行動予定は**「日付をまたいだら前の日の日記を書く」1つだけ**。
- 主人の入力が来たら、すべての行動予定を非活性に戻し、走っている仕事を `cancel()` で止める（4.2 の 1）。入力が止んで一定時間（既定60秒）経ってから、活性の計算を再開する。
- 段2は、ここに欲求（話したい・知りたい・振り返りたい・休みたい）の行動予定を足す。ループと取り消しの口は変えない。

### 4.8 終了（BH-16・Bug-4・Bug-6。L-3・B-9）

- **終了処理は核の中の1か所だけ。**1回目の呼び出しだけが進み、2回目以降は「もう終わっている途中」とログに残して何もしない。
- 段1の終了の経路：トレイの「終了」／キャラ作りの画面を閉じる／起動したコンソールでの中断（開発のとき）／Windows のサインアウト・シャットダウン（Qt のセッション終了）。
  どれも核の終了処理を呼ぶ。
- 順番：`lifecycle` に開始 → 窓とトレイを消す → メインループを止める → 今日の日記（4.6。サインアウトのときは作らない）→ SQLite を閉じる →
  `lifecycle` に完了 → 画面のスレッドに終わりを知らせる → Qt のイベントループを抜けてプロセスが終わる。
- 強制終了（`taskkill /F`・電源断）は終了処理を通らない。**それでも会話は1発言ごとにコミット済みなので残り**、日記は次の起動で埋まる（BH-13・BH-15）。

### 4.9 突っつき（BH-05。保護指定1）

- 縁の押下を核へ渡す。核は低い effort・短い上限で、キャラとして一言の反応を作り、欄に出す（発言の種類＝突っつきで残す）。
- 反応を作っている間の突っつきは捨てる（重ねない）。前の反応から数秒は反応しない（うるさくしない）。

## 5. 保護指定

### 保護指定1：ヘリを突っつくと反応する

窓の外周 8px をヘリとし、押されたら「突っつき」として核へ渡し、キャラの一言を返す（3・4.9。BH-05）。
位置（上下左右と座標）はログに残し、段2以降の部位判定（「頭を撫でた」等）に使える形にしておく。画像ボディを足しても、ヘリの判定はそのまま使う。

### 保護指定2：メインループは止まらない。行動予定の活性でやる・やらないを決める

核の常駐タスクとしてメインループを置き、段1で行動予定を1つ（日付またぎの日記）持たせる（4.7）。
**入力で全部の行動予定を引く口**と、**走っている仕事を取り消す口**（ADR 0004）を段1で作り、段1の行動予定で実際に通す。段2はここに足すだけで済む。

### 保護指定3：主人が書いた部分以外は、AI が調べながら作る。その過程のゆらぎが唯一無二にする

キャラ作りの5段のうち、2（連想の選び）と3（調べる語の選び・調べた結果）に核の乱数と検索の時機を入れ、LLM のゆらぎと掛け合わせる（4.3。BH-10・BH-11）。
主人が書いた部分（既存イメージの記述、おまかせのキーワード）は、統合で消さずに残す。生まれた経緯は `origin.md` に残し、種は残さない。

### 保護指定4：主人が書ける部分と書けない部分を分ける

`docs/concept.md` §8.7 の権限マトリクスを、**書く口があるか無いか**で実装する（2 の最後）。

| 物 | 主人 | AI（核） |
|---|---|---|
| 根っこ・口調の見本 | 凍結前：キャラ作りの画面で／凍結後：エディタで手で（気づいて問う。BH-21） | 凍結前の `seal()` だけ（BH-19） |
| 主人について（L6） | 「自分について…」の小窓（BH-20） | はっきり言われたことだけ上書き、履歴を残す（BH-18） |
| 関係の変化（L2・L5） | 承認／見送る | 提案だけ（BH-22） |
| 会話の記録・日記（L3・L4） | 書く口なし（BH-20） | 足すだけ |
| 設定 | `config.toml` と画面の「最前面」 | 書かない（窓の位置と最前面を残すのは、主人の操作を写すだけ） |

## 6. 禁則をどう担保するか

| 禁則（`CLAUDE.md` §0） | 設計での担保 |
|---|---|
| **凍結核を AI が書き換えない** | `persona` の書く口は `seal()` だけで、`persona_seal` があれば拒む。起動のたびにハッシュを比べ、違えば主人に問う（2・4.1。BH-19・BH-21） |
| **主人の入力が最優先**（自律のふるまいは入力で即座に引く） | 入力は画面から核へ最初に渡し、核は保存の次に行動予定を全部引いて仕事を取り消す（4.2・4.7）。LLM は核の中で待ち、画面のスレッドを止めない（ADR 0004。S5 で実測） |
| **記憶を失わない** | 1発言ごとにコミット（WAL・`synchronous=FULL`）。終了処理は1か所・1回。日記は3つの時に作り、日付の一意制約で重複しない。強制終了でも発言は残り、日記は次の起動で埋まる（4.2・4.6・4.8。BH-13・BH-15・BH-16） |
| **ゆらぎはテストで外から固定できる**（同じ入力から同じキャラは生まれない） | 本番は OS の乱数と LLM のゆらぎと検索の時機で毎回違う。テストでは、キャラ作りに種を固定した乱数の生成器を渡し、LLM の口を決まった返事の偽物に替える（`config.toml` の呼び先。BH-37）。種は本番では残さない（4.3・BH-10） |
